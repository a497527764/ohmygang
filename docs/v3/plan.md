# lolGang 3.0 — 需求和计划

> 状态：计划稿（2026-11-04 第二版），等所有者审阅后再动代码。界面风格、语音方式、说话键、图标已由所有者定下（第 2 节）。
> 第二版改动：加入聊天框和历史记录（文字、语音、信号、表情都记，语音能点着回放，解散队伍时所有人清空），打字改成平时隐藏的聊天框（第 2、3.5、3.6、4、5、6 节）。
> 2.0 的需求和架构见 [../v2/](../v2/)，这里没提到的部分照 2.0 不变。

## 1. 目标

更像 lolPing 的 Rust 版本：信号、表情、组队、队伍面板、投票、打字是主体；去掉 2.0 自己加的「对线叠心之钢」；
加上按住说话的语音，以及一个平时隐藏、按快捷键弹出的聊天框，里面有队伍的历史记录（文字、语音、信号、表情）。界面换成英雄联盟客户端的样子，说明文字大幅减少，所有按键集中到一页，顺手把空闲时的资源占用降下来。

## 2. 所有者已定的决定（2026-11-04）

| 事项 | 决定 |
|---|---|
| 界面风格 | 英雄联盟客户端风格：深蓝黑底、金色细边、浅金文字，按钮、开关、滑条仿客户端 |
| 语音 | 按住说话，松开就停；队友那边直接播放 |
| 说话键 | 默认 V，在「快捷键」页可以改成任何键或鼠标侧键 |
| 程序图标 | 原创：蓝金色的信号菱形，不用游戏原图 |
| 心之钢 | 整个对线玩法去掉，包括音效、图片、排行榜、托盘项、快捷键 |
| 聊天框 | 平时隐藏；按打字快捷键（默认 Alt+T，可改）弹出，上面是历史记录，下面是输入框 |
| 历史记录 | 记文字、语音、信号、表情；语音像微信语音一样点播放按钮回放；解散队伍时，队伍里所有人的这些记录全部清空 |
| 离线的消息 | 不补：记录就是这台电脑在线时收到的，不在线时别人发的上线后看不到 |
| 退出队伍 | 清空自己这边这个队伍的全部记录（被踢出也一样） |

## 3. 改动

### 3.1 去掉心之钢（对线模式）

要删的（2.0.2 里约 170 处引用）：

| 地方 | 内容 |
|---|---|
| Rust 模块 | `heartsteel.rs`（叠层重放）、`laning.rs`（对线判定）、`lane.rs`（对线线程，开着时每 33 毫秒走一步） |
| 协议和核心 | 不再产生 Hit 事件（kind 9）和 Cursor、Charge 实时帧；`Core::hit`、`my_last_hits`、`CoreEvent::HitLanded`、`rooms::apply_hits` |
| 手势和设置 | 「普攻」（Attack）、对线快捷键（Ctrl+Alt+L）、`laning_hotkey` |
| 托盘、命令 | 托盘「对线模式」、`laning_set`、状态里的 `laning` |
| 透明窗口 | `src/overlay/lane.ts`、对线和心之钢爆炸的样式、`#lane` 层 |
| 控制面板 | 队伍页的对线卡片和排行榜、队员的层数和生命值、Tab 面板里的层数 |
| 素材 | `src/assets/heartsteel.png`、`heartsteel.mp3`、`docs/心之钢.*`；程序图标（现在就是心之钢的图） |

- **兼容**：不升协议版本。2.0 的队友发来的 Hit 事件、对线帧，3.0 收到后忽略；3.0 的语音帧，2.0 收到后忽略。
  所以 2.0 和 3.0 的人仍能在一个队伍里（各自少一样功能），自动更新会把大家带到 3.0。
- **存储**：`members` 表的 `stacks`、`taken` 两列留着不用，不改旧库，免得迁移出错。
- **图标**：原创 SVG（英雄联盟信号那种菱形加波纹，蓝色和金色），用 `tauri icon` 生成全部尺寸；控制面板左上角、托盘、安装包都换成它。

### 3.2 界面：英雄联盟客户端风格

- **配色**：底色 #010a13 / #0a1428，卡片 #0f1d2b 带 1 像素金边（#785a28，高亮 #c8aa6e），文字 #f0e6d2，次要文字 #a09b8c，
  强调色海克斯蓝 #0ac8b9；危险操作 #be1e37。透明窗口上的轮盘、面板、投票窗口已经是这个味道，控制面板跟它们统一。
- **控件**：金边渐变按钮（主按钮金底深字）、仿客户端的开关和滑条、自绘下拉菜单（沿用 2.0.1 的做法，换配色）、录键框。
- **浅色主题**：「浅色客户端」——羊皮纸底（#f0e6d2 系）配深蓝字和金边；跟随系统时在深浅之间切。
- **导航**：左侧窄栏，图标加名字，选中项左边一条金色竖线；分页：队伍、信号、表情、语音、快捷键、功能、关于。
- **少写字**：每一项只留名字（必要时一个短词）；需要解释的放进 ⓘ 悬停提示；整段说明和例子删掉。
  现在 5 个页面里有 15 处说明文字，目标是页面上不再出现整句说明。
- **外观页**：去掉，「主题」并入功能页。

### 3.3 快捷键页

一页列出所有按键，都能当场录：

| 按键 | 默认 |
|---|---|
| 信号轮盘（按住拖动） | Alt |
| 表情轮盘（按住拖动） | Ctrl |
| 说话（按住） | V |
| 暂停 / 恢复 | Ctrl+Alt+P |
| 打开聊天框 | Alt+T |
| 队伍面板（按住） | Tab |

- 其他页上的按键设置都移到这里。
- 撞键规则仍由 Rust 的 `settings2::normalize` 管（同一个键不能两用）；被换掉时这一行直接显示换成了什么、为什么。

### 3.4 语音（按住说话）

- **技术选择**：录音和播放都在 Rust，用 `cpal`（Windows WASAPI、macOS CoreAudio、Linux ALSA）。编码用纯 Rust 的 `opus-rs`：
  它移植自官方 libopus 1.6，不需要 C 编译器。本机实测：16 kHz 单声道 16 kbps，1 秒约 2 KB，编码加解码 1 秒音频用 7 毫秒，
  解码后能量保留 98%。
  另一个办法是带 C 源码的 `opus` crate，但它要用 CMake 编译 libopus，本机的 CMake 4.1 不认 VS 2026 的生成器，编不过。
- **说话键 V 的处理**：按下就开始录（不吃掉第一个字），拦下这个键。
  - 按住不到 0.3 秒就松开，算「点了一下」：丢掉录音，补打一个 V，打字照常。
  - 按住期间按了别的键，说明在打字：停止录音，把 V 补打出去，后面的键照常。这和 2.0 自定义触发键的「补打」是同一个思路。
  - 一次最长 30 秒，到时自动结束。
- **传输**：每 400 毫秒的 Opus 帧打成一个实时帧 `Voice{流号, 序号, 帧们, 结束}`，约 1 KB，装得进一个 1200 字节的包；
  局域网和中继都走。中继每秒约 2.5 包，发送预算是每秒 5 包，给信号留出余量。帧有签名，只收队员的。
- **播放**：收端按流号、序号排好，缓冲约 0.5 秒再放；丢了的帧用 Opus 的丢包补偿。一个输出流，几个人同时说就混音。
  语音有单独的音量，可以关掉接收。
- **存进历史记录**：每段话说完（自己的和队友的）整段存下来，在聊天框里显示成一条语音（时长加播放按钮），见 3.6。
  没在线时队友说的话收不到，也就不会有记录。
- **显示**：
  - 透明窗口右下角显示「正在说话」的人（名字加话筒图标，颜色和他的信号标签一样）；
  - 自己按住时显示「正在录音」和剩余秒数；
  - Tab 面板里正在说话的人亮起。
- **语音页**：开关、说话键（链接到快捷键页）、麦克风（默认跟随系统，可选设备）、接收音量、试音（录 3 秒回放给自己听）。
- **各平台**：macOS 要在 Info.plist 写麦克风用途说明，第一次会弹系统授权；Linux 的 CI 加装 `libasound2-dev`；
  Windows 要在系统设置里允许桌面应用使用麦克风（关着时语音页提示）。

### 3.5 聊天框和打字

- **平时隐藏**：2.0 的小输入框换成聊天框，平时看不见。按打字快捷键（默认 Alt+T，在快捷键页可改）在鼠标所在的屏幕弹出，
  再按一次或按 Esc 收起；点到别的程序也收起。只有在队伍里时这个快捷键才拦。
- **布局**：上面是这个队伍的历史记录（最新的在最下面，打开时滚到底），下面是输入框；回车发送，发完不关，可以接着说。
  /ff、/noff、/ready 这些指令照旧。
- **聊天框里的语音**：可以直接按住说话键说话，说完就作为一条语音出现在记录里。
- **屏幕上的字照旧**：发出去的话仍然出现在队友屏幕上（原处冒出或弹幕），并且：
  - **字号**可调，默认比现在大（约 28 像素）；
  - **字幕特效**（类似剪映的字幕模板），功能页里挑一种，能在屏幕中间预览：描边大字（白字黑描边）、金色渐变（客户端金）、
    霓虹发光、逐字弹跳、打字机（逐字出现）、抖动强调。发言人名字的标签保留，颜色和信号标签一致。

### 3.6 历史记录

- **记什么**：这台电脑在队伍里时发出和收到的——
  - 文字：谁、什么时候、说了什么；
  - 语音：谁、什么时候、多长，点播放按钮回放（像微信语音）；正在播放时按钮变成停止；
  - 信号：谁、什么时候、什么信号（带图标），比如「阿钢 21:03 发了『危险』」；
  - 表情：谁、什么时候、什么表情（带小图）。
  自己发的也记。聊天框顶部可以只看某一类（全部、文字、语音、信号和表情）。
- **存在哪**：本机的 `gang2.db` 新加一张表（数据库第 4 版），按队伍分开；语音存的是 Opus 帧（30 秒约 60 KB）。
  每个队伍最多留最近 2000 条，语音总共最多 100 MB，超了删最旧的。
- **清空**：
  - **解散队伍**：每个人的程序收到「解散」事件时，删掉这个队伍的全部记录（文字、语音、信号、表情）。
    解散时不在线的人，下次上线同步到解散事件时再删，所以最后所有人都清空。
  - **退出队伍**（所有者已定）：自己走时，删掉自己这边这个队伍的全部记录；别人的记录不动。
    被踢出也一样，因为被踢的程序本来就是自己退出队伍。
- **不补齐**（所有者已定）：记录是每台电脑自己收到的那些，不在队伍之间补齐；不在线时别人发的东西，上线后看不到。
  文字和语音因此继续走实时帧，不进队伍的事件记录，也不给中继加补齐的负担。

### 3.7 性能

**先量再改。** 2.0.1 装好运行 36 分钟时，lolGang 一共 12 个进程、约 490 MB 内存。空闲时 WebView2 的几个进程一直在用 CPU：

| 进程 | CPU 时间 |
|---|---|
| GPU 进程 | 约 35 秒 |
| 两个页面进程 | 约 30 秒、16 秒 |

要做的：

1. 用 CDP 的性能指标逐个页面找出空闲时还在跑的东西（定时器、动画、透明窗口的重绘），改掉。
2. 控制面板关掉时销毁它的网页（主窗口的页面进程占几十 MB），打开时再建。
3. 队伍页每 3 秒、状态每 5 秒的轮询，改成有变化才推送。
4. 对线线程、对线的透明窗口绘制随玩法删掉。
5. 改完在同样的条件下再量一次，前后数字写进提交说明和发版说明。

## 5. 风险和要注意的

- **语音的音质和延迟**：局域网约 0.5–1 秒；走中继要看中继延迟，可能 1–3 秒。先保证「能听清、不卡死信号」，不追求实时通话那样的低延迟。
- **默认说话键 V**：快速点按会补打出来，但有的输入法或游戏可能对「先拦下再补打」敏感；在快捷键页可以换成鼠标侧键。
- **`opus-rs` 较新**（2026 年发布），万一在某个平台出问题，退路是改用带 C 源码的 `opus` crate（要在 CI 和本机配好 CMake）。
- **浅色主题**在英雄联盟风格下要单独设计，做出来如果不好看，可以只留深色（需要所有者确认）。
- **macOS、Linux 的语音**和输入一样只能在 CI 上编译，真机没测过，标「实验版」。
- **历史记录占空间**：信号发得多时记录涨得快，所以每个队伍限 2000 条、语音限 100 MB；需要的话以后加「手动清空」按钮。
- **聊天框要拿焦点**：弹出时会从游戏里抢走键盘（不然打不了字），收起后焦点还给原来的程序。全屏独占模式的游戏可能会被切出去，
  无边框窗口模式没问题。
