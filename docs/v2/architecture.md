# 钢一下 2.0 — 架构

> 状态：草案（2026-11-03 第三版），等所有者审阅。需求见 [requirements.md](requirements.md)。1.x 的架构见 [../architecture.md](../architecture.md)，其中网络、加密、事件签名和状态同步在 2.0 继续使用。
> 第二版改动：加入 macOS、Linux 和自动更新（第 2、3、9、10、11 节）。
> 第三版改动：只有 Windows 正式支持和真机验收；macOS、Linux 照 lolPing 的做法实现，出「实验版，未测试」的安装包（第 10、12、13 节）。

## 1. 总体

一个 Tauri 进程：Rust 负责输入、窗口、网络、叠层、存储和更新；画面在几种 WebView 窗口里（Windows 是 WebView2，macOS 是 WKWebView，Linux 是 WebKitGTK）。

```
┌─────────────────────────── 钢一下（一个进程）───────────────────────────┐
│ Rust                                                                  │
│  input     输入线程：各平台的全局键鼠监听，把事件交给                     │
│            └ gesture：手势状态机（纯函数，移植 lolPing 的 decision.cpp） │
│  overlay   每个显示器一个透明置顶窗口；显示器编号、坐标换算、空闲时挪开     │
│  team      队伍：建队、进队、成员、状态事件（沿用 1.x 的事件和同步）        │
│  live      实时帧：在线状态、鼠标、信号、表情、文字、投票、充能（不入库）    │
│  laning    对线规则（纯函数）：700 码、充能、命中、冷却                     │
│  heartsteel 叠层重放（纯函数）：Hit 事件 → 层数和生命值                    │
│  emotes    表情库：内置清单、导入图片、静态图在队友间传                     │
│  net       局域网 UDP + Nostr 中继 + 发送预算 + 防灌水（沿用 1.x）          │
│  update    检查、下载、校验、安装更新（tauri-plugin-updater）              │
│  store / settings / tray / platform                                   │
├───────────────────────────────────────────────────────────────────────┤
│ WebView 窗口                                                           │
│  控制面板（React，沿用 1.x 的界面风格）                                   │
│  overlay × 显示器数（原生 TS + DOM，移植 lolPing 的轮盘、信号、表情动画）   │
│  打字框（拿焦点）、Tab 面板（可点但不抢焦点）                              │
└───────────────────────────────────────────────────────────────────────┘
```

和 lolPing 的区别：lolPing 把输入放在单独的 C++ 进程，因为 Electron 主线程会卡，而 Windows 会悄悄移除响应慢的钩子、macOS 会停用超时的事件监听。Rust 没有这个问题：输入跑在专门的线程上，回调里只做纯计算，结果用不阻塞的通道交出去。以后真遇到超时，再把这个线程挪到子进程，接口不变。

源码按平台分文件：共用的逻辑不认平台；各平台的实现放在 `win32.rs`、`macos.rs`、`linux.rs` 里，用 `#[cfg(target_os = ...)]` 选择。改一个平台的文件不影响其他平台（同 lolPing 的约定）。

## 2. 输入（`input`）

### 2.1 共用部分

- 键统一用 Windows 的虚拟键码表示（同 lolPing）；各平台把自己的键码换成虚拟键码，换算表是纯函数，有测试。
- 当前配置（触发键、开关、对线模式、是否在队伍里）放在原子量里，回调直接读，不加锁等待、不做 IO。
- 回放自己注入的事件时打标记，监听到带标记的事件直接放行。
- 进程退出或崩溃时监听随进程消失，键鼠不会被卡住。

### 2.2 手势状态机（`gesture`，纯函数，表驱动测试）

逐条移植 lolPing 设计文档 5.1、5.2、13、14 节和 `decision.cpp`、`macinput.cpp`：
- 状态：`Idle`、`Pending`（按住触发键按下左键，还没拖过阈值）、`Wheel`（轮盘打开）。
- 两个轮盘：信号、表情；两个都匹配的按下当作有歧义，原样放行。
- 拦下的按下必须配对拦下抬起，或者两个都回放，绝不留下没配对的按下。
- 10 秒看门狗、右键或 Esc 取消、暂停快捷键、打字键、Tab 面板键、全屏游戏放行（只在 Windows）。
- 2.0 新增：对线模式打开且有对手充能完成时，触发键加单击判为「普攻」，拦下并交给 `laning`；否则照旧（放行或放一个信号）。

### 2.3 各平台

| 平台 | 做法 | 依赖 |
|---|---|---|
| Windows | 一个线程装 `WH_MOUSE_LL` 和 `WH_KEYBOARD_LL`，跑自己的消息循环。拦下就返回 1；回放用 `SendInput`，标记放在 `dwExtraInfo`。用过 Alt、Win 后在弹起前注入无效键 `VK_NONAME`（0xFC），免得弹出菜单。 | `windows` |
| macOS | 一个线程建会话级的 `CGEventTap`，跑自己的 `CFRunLoop`。拦下就返回空；回放用 `CGEventPost`，标记放在 `kCGEventSourceUserData`。修饰键从 `FlagsChanged` 换算成按下抬起；拖动事件一律放行（拦了会卡住光标，lolPing 的实测结论）。监听被系统因超时停用时重新启用。需要「辅助功能」权限，没有就报 `noAccess`，控制面板提示授权。不提供 Caps Lock 当触发键。实现：`input/macos.rs`（实验版，未在真机上测试）。 | 直接声明 CoreGraphics、CoreFoundation 的几个函数（`extern "C"`），不加依赖 |
| Linux（X11） | 用 XInput 2.1 原始事件看键盘；对触发键加左键做被动抓取（passive grab），普通点击用 `ReplayPointer` 交还给程序；短按的回放用 XTest。启动时检查会话，Wayland 或 XWayland 直接报不支持。不提供 Caps Lock 当触发键；窗口管理器占用了同一个组合键时记日志并在控制面板提示换键。键码按 XKB 物理键名换成 Windows 键码，认不出再看 keysym。实现：`input/linux.rs`（实验版，未在真机上测试）。 | `x11rb`（纯 Rust，带 XInput、XTest、XKB 扩展） |

### 2.4 `unsafe`

Windows 和 macOS 的系统接口必须用 `unsafe`。只放在这几个文件里：`input/win32.rs`、`input/macos.rs`、`overlay/win32.rs`、`overlay/macos.rs`。每处旁边写清不变量（句柄或指针的来源、生命周期、在哪个线程调用），对外只暴露安全的函数。Linux 用 `x11rb`，不需要 `unsafe`。其他模块不写 `unsafe`。

## 3. 透明窗口（`overlay`）

### 3.1 共用部分

- 每个显示器一个窗口：透明、无边框、不在任务栏、不拿焦点、始终置顶、鼠标穿透。
- 显示器变化（插拔、分辨率、缩放、游戏改分辨率）时重建；每次要画新东西前先比对一次显示器，防止漏掉变化事件。
- 显示器编号：主显示器是 1 号，其余从左到右、从上到下。队友的信号、鼠标按「几号显示器 + 宽高比例」传，落到自己同号显示器的同一比例处，没有这一号就落到 1 号。所以不同平台、不同分辨率之间也能对上。
- 画面：移植 lolPing `src/renderer/overlay` 的轮盘（SVG）、信号动画、表情舞台、文字排布和音效（Web Audio，开窗口时一次解码）。对线模式下另画对手的小英雄、700 码圈、充能圈、冷却倒计时和心之钢爆炸特效。
- 字体：不再写死 Windows 字体，按平台选系统字体（Windows 微软雅黑和 Segoe UI，macOS 苹方和 SF，Linux Noto Sans CJK）。

### 3.2 各平台

| 平台 | 做法 |
|---|---|
| Windows | 钩子给物理像素，按显示器缩放换成窗口内的 CSS 像素。窗口底边少一个像素，免得资源管理器把它当全屏程序、压下任务栏。没东西可画时把窗口挪到显示器外（留一个像素保持缩放），QQ、微信截图工具就不会把它当成要截的窗口；有东西要画时挪回并用 `SetWindowPos(HWND_TOPMOST)` 重新置顶，用 `WS_EX_NOACTIVATE` 保证不抢焦点。 |
| macOS | 事件坐标是「点」；Tauri 的显示器矩形是物理像素（点乘缩放），所以输入层按鼠标所在显示器的缩放（显示模式的像素宽 ÷ 点宽）换成物理像素，后面和 Windows 走同一套换算。Tauri 透明窗口要打开 `macOSPrivateApi`。窗口设为出现在所有桌面空间（`visible_on_all_workspaces`）。2.0 先用 Tauri 的不可聚焦窗口当 Tab 面板和投票窗口，没有转成 NSPanel；能不能叠在全屏应用上、会不会激活应用，要在真机上看（实验版）。 |
| Linux | 需要窗口合成器才能透明；鼠标穿透用窗口的输入形状（Tauri 的 `set_ignore_cursor_events`）；置顶和不进任务栏用窗口管理器提示。缩放和 lolPing 一样固定为 1，和 X11 的根窗口坐标一致；控制面板因此不跟随桌面的高分屏缩放。 |

## 4. 队伍（`team`）和状态同步

沿用 1.x 的事件模型：每条状态事件由作者用 Ed25519 签名、按作者和序号排列，经 Have/Want 补齐，所有人推导出一样的队伍状态（1.x 架构第 4、7、8 节）。2.0 的改动：

- 只留状态流：`TeamCreate`、`Join`、`Leave`、`Profile`、`Rename`、`Dissolve`、`Hit`。1.x 的聊天流、聊天补齐（WantFloors/Floors）、图片、清空记录、规则修改都去掉。
- 包头的协议版本从 1 改为 2；1.x 的程序收到会提示「对方版本不同」。
- 队伍码沿用 1.x 的格式（另换前缀，和 1.x 的群码区分开）。
- 三个平台用同一套协议，可以在同一个队伍里。

## 5. 实时帧（`live`）

不入库、不补齐，丢了就丢了。每帧都带发送者短 ID 和序号，并用发送者的身份密钥签名；收的人按序号窗口和 ±10 分钟时间戳挡住重放（lolPing 12 节）。

| 帧 | 内容 | 频率 |
|---|---|---|
| Presence | 状态（在线、暂停、离开电脑）、是否开对线模式、程序版本、平台、表情轮盘上的自定义图哈希 | 局域网 2 秒一次，中继 5 秒一次 |
| Cursor | 显示器号、x、y（0–65535 比例）、序号 | 只在对线模式、鼠标移动时发；局域网最多每秒 30 次，中继每秒 3 次 |
| Charge | 对谁开始充能、取消 | 状态变化时发 |
| Ping / Emote / Text / Alive | 同 lolPing，位置用显示器号加比例 | 按发送预算 |
| Vote / Ballot | 同 lolPing 14 节 | 同上 |
| Want / Chunk | 自定义表情静态图分片 | 同 lolPing 13 节 |
| Bye | 离开队伍 | 一次 |

发送预算：中继沿用每秒 5 条、突发 10 条，优先级从高到低：信号表情文字命中 > 在线状态、充能、Have > 鼠标位置（只留最新一条）> 补齐。局域网不受这个限制，只受防灌水限制。

## 6. 对线和心之钢

### 6.1 对线判定（`laning`，纯函数）

输入：自己的鼠标（显示器号、坐标）、每个对手最新的鼠标帧（带收到时间）、时间。输出：每个对手的状态（远、在范围内充能中、充能完成、冷却中）和出手结果。

- 对手的位置：用最近两帧做线性插值，超过 1 秒（中继 2.5 秒）没新帧就当离线，充能中断。
- 范围（「700 码」）：同一号显示器上，距离不超过该显示器较短边的 35%（1080p 上约 380 像素）。这个比例是常量，实测后再调。
- 充能：在范围内连续 3 秒；出范围、对手关掉对线模式、对手掉线都会中断，重新计时。充能开始和中断各发一次 Charge 帧。
- 出手：信号触发键加单击。落点离某个充能完成的对手不超过较短边的 6%（至少 60 像素）就算命中，所有满足条件的对手都命中。点空了，这次的充能全部作废。
- 判定以出手一方看到的位置为准（「射手优先」），所以跨网时也能打中；对手看到的是事后的结果。

### 6.2 Hit 事件和重放（`heartsteel`，纯函数）

- Hit 事件（状态流，签名）：`target`（对手完整公钥）、`charged_ms`（这次充能用了多久）。
- 有效条件（所有人用同一套规则重放，所以层数一致）：
  - 作者和目标在事件时间都是队员，目标不是自己；
  - `charged_ms ≥ 3000`；
  - 作者对同一个目标的上一条有效 Hit 至少早 30 秒（按作者时间，作者时间严格递增）；
  - 不在队伍解散之后。
- 层数 = 作者的有效 Hit 数；被叠次数 = 以他为目标的有效 Hit 数。
- 生命值（整数运算，各端结果一样）：初始 1500；每叠一层，伤害 = 70 + 当前生命值 × 6 / 100，生命值 += 伤害 / 10。数值仿照心之钢「伤害随最大生命值增长、每层得到伤害 10% 的永久生命值」。
- 实时特效：收到的 Hit 有效、而且是实时帧带来的，就在目标位置放心之钢爆炸特效和音效；补齐来的旧 Hit 只更新数字。

### 6.3 跨网的实时性

- 局域网：每秒 30 帧，几毫秒延迟，很顺。
- 跨网：公共中继延迟 0.2–0.5 秒，每秒只发 3 帧，靠插值补帧，看起来会一顿一顿。命中按出手方判定，所以仍然能玩。
- 打洞直连仍是以后的事；做了以后跨网也能每秒 30 帧。

## 7. 表情（`emotes`）

- 内置表情：lolPing 的 `assets/emotes`（动画 WebP、图标、音效）和它的清单。
- 导入：静态图压到 12KB、160 像素以内，按 SHA-256 前 32 位十六进制命名；可另存原动画（5MB 以内）和音效（1MB、5 秒以内）。规则同 lolPing 13 节。
- 传图：在线状态里带上自己轮盘上的自定义图哈希；没有的人用 Want 要，用 Chunk 分片发静态图，收齐核对哈希再存进缓存（最多 200 张、4MB）。动画和音效不传。
- 动画 WebP 在三种 WebView 里都能播；音效格式用 OGG（WebKitGTK 靠 GStreamer 解码，Linux 包要声明依赖）。

## 8. 存储、设置和系统服务

- 新数据文件 `gang2.db`，放在各平台的应用数据目录（Windows `%APPDATA%`，macOS `~/Library/Application Support`，Linux `~/.local/share`），和 1.x 的 `lolgang.db` 放在同一目录；1.x 的文件不读、不删。身份在新库里重新生成。
- 表：身份、队伍、成员缓存、状态事件、设置；自定义表情放在 `emotes/` 目录，队友的静态图放在 `emote-cache/`。
- 设置项：lolPing 8.1 节的全部（触发键、拖动距离、单击信号、轮盘、快捷键、大小、时长、音量、静音、刻度声、开机启动、功能开关、打字键、面板键、文字样式），加上对线模式的快捷键、自动更新开关和 1.x 的主题、网络设置。macOS 上把 Caps Lock 触发键修正为 Option 或 Control（同 lolPing）。

| 服务 | Windows | macOS | Linux |
|---|---|---|---|
| 主密钥保存 | 凭据管理器 | 钥匙串 | Secret Service（GNOME 钥匙环、KWallet）；没有时提示安装 |
| 托盘 | 通知区域图标 | 菜单栏模板图标，控制面板关闭时隐藏程序坞图标 | AppIndicator（libayatana-appindicator） |
| 开机自启 | `tauri-plugin-autostart`（注册表 Run） | 登录项 | XDG `autostart` 目录 |
| 新消息提醒（1.x 的 `attention`） | 托盘红点、任务栏闪烁 | 菜单栏图标、程序坞跳动 | 托盘图标、窗口紧急提示 |
| 单实例 | `tauri-plugin-single-instance` | 同左 | 同左（经 D-Bus） |

现有的 `keyring` 4 要确认在 macOS 和 Linux 上打开了对应的后端；不行就按平台加特性或换成平台各自的实现。

## 9. 自动更新（`update`）

- 用 `tauri-plugin-updater`。更新清单 `latest.json` 和各平台的更新包放在 GitHub Release 里；程序访问 `https://github.com/<所有者>/<仓库>/releases/latest/download/latest.json`。
- 更新包用 Tauri 的更新签名（minisign）签名，公钥写进 `tauri.conf.json`，私钥只在 GitHub Actions 的 Secrets 里；下载后先校验签名，不对就放弃。
- 什么时候查：启动后 30 秒、之后每 6 小时，设置里可以关；托盘和关于页可以手动查。查到新版本只提示，用户点「更新」才下载安装，装完重启。
- 各平台的更新包：Windows 是 NSIS 安装包（按当前用户安装，不需要管理员）；macOS 是 `.app.tar.gz`；Linux 是 AppImage。deb 包装的程序查到新版本时只提示去下载。
- macOS 没有开发者签名时，每次更新后系统会把它当成新程序，要重新授权辅助功能（lolPing 同样）。控制面板检测到「系统说已授权但监听建不起来」时，教用户在列表里删掉再加回来。
- 版本号三处一致（`tauri.conf.json`、`Cargo.toml`、`package.json`），发版打 `v<版本>` 标签。

## 10. 打包和持续集成

- 产物：

  | 平台 | 安装包 | 更新包 |
  |---|---|---|
  | Windows | `lolgang_<版本>_x64-setup.exe`（NSIS） | 同一个安装包加签名 |
  | macOS | `lolgang_<版本>_aarch64.dmg`（临时签名 `-`） | `钢一下.app.tar.gz` 加签名 |
  | Linux | `lolgang_<版本>_amd64.AppImage`、`lolgang_<版本>_amd64.deb` | AppImage 加签名 |

- GitHub Actions：
  - `ci.yml`：每次推送在 Windows、macOS（Apple 芯片）、Ubuntu 上跑 `cargo test`、clippy、前端构建；Ubuntu 上另用 Xvfb 跑 X11 输入的集成测试（同 lolPing 的 `linux_x11_test`，不碰真实桌面）。
  - `release.yml`：推送 `v*` 标签时先建草稿 Release，三个平台各自打包、签名、上传，最后生成 `latest.json` 并发布。
- 开发机只有 Windows，所有者也没有 Mac 和 Linux 设备：macOS 和 Linux 的包只在 GitHub Actions 上打，标「实验版，未测试」；本机能做的是 Windows 的打包和全部纯逻辑测试。
- 推送代码和打标签发版都由所有者做。

- 纯函数单元测试（三个平台都在 CI 上跑）：手势状态机（移植 lolPing `helper_tests.cpp` 的用例）、macOS 和 Linux 的键码换算、轮盘选格、显示器编号和坐标换算、对线判定、叠层重放和生命值公式、帧的编解码和校验、投票计票、文字清洗、表情导入检查、更新清单解析。

- Linux 输入集成测试：在 Xvfb 里起一个接收窗口，用 XTest 发输入，验证点击放行、短按回放、两个轮盘、取消、暂停（不碰真实桌面）。

## 13. 风险

| 风险 | 应对 |
|---|---|
| 全局键盘钩子可能被杀毒软件当成键盘记录器 | 和 lolPing 一样无法完全避免；只看按键码、不记录、不外发，在 README 说明 |
| 钩子或事件监听因超时被系统移除 | 回调只做纯计算；看门狗检测失效后重装或重新启用，并在托盘提示 |
| macOS 没有开发者签名：首次打开要手动放行，每次更新要重新授权辅助功能 | 控制面板一步步引导；所有者可以决定买苹果开发者账号 |
| macOS、Linux 没有真机测试，可能装上就有问题 | 第一阶段就把三平台的 CI 建起来；系统接口按 lolPing 已验证的做法写；安装包标实验版，用户遇到问题再修 |
| Linux 桌面差异大（Wayland、窗口管理器占键、托盘） | 只支持 X11，启动时检测并说明；冲突时提示换键 |
| WebKitGTK、WKWebView 和 WebView2 的表现差异（透明、自动播放声音） | 每个平台第一次跑通时专门验证透明窗口和声音 |
| 安装包变大（素材约 60MB） | 只打包清单里用到的文件 |
| 跨网对线卡顿 | 插值、射手优先；以后做打洞直连 |
| 公共中继限流 | 鼠标帧最低优先级、只留最新一条 |
| 更新签名私钥泄露 | 只放在 GitHub Secrets；泄露就换钥匙、发一个新版本 |
