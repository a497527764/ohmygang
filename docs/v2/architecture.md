# 钢一下 2.0 — 架构

> 状态：草案（2026-11-03），等所有者审阅。需求见 [requirements.md](requirements.md)。1.x 的架构见 [../architecture.md](../architecture.md)，其中网络、加密、事件签名和状态同步在 2.0 继续使用。

## 1. 总体

一个 Tauri 进程：Rust 负责输入、窗口、网络、叠层和存储；画面在几种 WebView 窗口里。

```
┌─────────────────────────── 钢一下（一个进程）───────────────────────────┐
│ Rust                                                                  │
│  input     钩子线程（WH_MOUSE_LL + WH_KEYBOARD_LL，自己的消息循环）       │
│            └ gesture：手势状态机（纯函数，移植 lolPing 的 decision.cpp） │
│  overlay   每个显示器一个透明置顶窗口；显示器编号、坐标换算、空闲时挪开     │
│  team      队伍：建队、进队、成员、状态事件（沿用 1.x 的事件和同步）        │
│  live      实时帧：在线状态、鼠标、信号、表情、文字、投票、充能（不入库）    │
│  laning    对线规则（纯函数）：700 码、充能、命中、冷却                     │
│  heartsteel 叠层重放（纯函数）：Hit 事件 → 层数和生命值                    │
│  emotes    表情库：内置清单、导入图片、静态图在队友间传                     │
│  net       局域网 UDP + Nostr 中继 + 发送预算 + 防灌水（沿用 1.x）          │
│  store / settings / tray                                              │
├───────────────────────────────────────────────────────────────────────┤
│ WebView 窗口                                                           │
│  控制面板（React，沿用 1.x 的界面风格）                                   │
│  overlay × 显示器数（原生 TS + DOM，移植 lolPing 的轮盘、信号、表情动画）   │
│  打字框（拿焦点）、Tab 面板（可点但不抢焦点）                              │
└───────────────────────────────────────────────────────────────────────┘
```

和 lolPing 的区别：lolPing 把钩子放在单独的 C++ 进程，因为 Electron 主线程会卡，而 Windows 会悄悄移除响应慢的低级钩子。Rust 没有这个问题：钩子跑在专门的线程上，回调里只做纯计算，结果用不阻塞的通道交出去。以后真遇到超时，再把这个线程挪到子进程，接口不变。

## 2. 输入（`input`）

### 2.1 钩子线程

- 一个线程安装 `WH_MOUSE_LL` 和 `WH_KEYBOARD_LL`，跑自己的消息循环；回调里调 `gesture::decide`，决定放行还是拦下，再把事件 `try_send` 给主逻辑。回调里不加锁等待、不做 IO。
- 当前配置（触发键、开关、对线模式、队伍里没有）放在原子量里，回调直接读。
- 回放：放行一个被暂扣的点击时用 `SendInput`，并在 `dwExtraInfo` 打自己的标记，钩子看到带标记的事件直接放行。
- Alt、Win 弹菜单：手势用过修饰键时，在它弹起前注入一个无效键（`VK_NONAME`，0xFC），和 lolPing、AutoHotkey 一样。
- 进程退出或崩溃时钩子随进程消失，键鼠不会被卡住。

### 2.2 手势状态机（`gesture`，纯函数，表驱动测试）

逐条移植 lolPing 设计文档 5.1、5.2、13、14 节和 `decision.cpp`：
- 状态：`Idle`、`Pending`（按住触发键按下左键，还没拖过阈值）、`Wheel`（轮盘打开）。
- 两个轮盘：信号（默认 Alt）、表情（默认 Ctrl）；两个都匹配的按下当作有歧义，原样放行。
- 拦下的按下必须配对拦下抬起，或者两个都回放，绝不留下没配对的按下。
- 10 秒看门狗、右键或 Esc 取消、暂停快捷键、Alt+T 打字键、Tab 面板键、全屏游戏放行（`gameCheck`）。
- 2.0 新增：对线模式打开且有对手充能完成时，Alt+单击判为「普攻」，拦下并交给 `laning`；否则照旧（放行或放一个信号）。

### 2.3 `unsafe`

调 Win32 接口（安装钩子、`SendInput`、窗口样式、前台全屏判断）必须用 `unsafe`。只放在 `input/win32.rs` 和 `overlay/win32.rs` 两个文件里，每处旁边写清不变量（句柄来源、生命周期、在哪个线程调用），对外只暴露安全的函数。其他模块不写 `unsafe`。

## 3. 透明窗口（`overlay`）

- 每个显示器一个窗口：透明、无边框、不在任务栏、不拿焦点、始终置顶、鼠标穿透。底边少一个像素，免得资源管理器把它当全屏程序、把任务栏压下去（lolPing 6 节）。
- 没东西可画时把窗口挪到显示器外面（留一个像素在本显示器上，保持缩放），QQ、微信截图工具就不会把它当成要截的窗口；有东西要画时挪回来并重新置顶（lolPing #127）。
- 显示器变化（插拔、分辨率、缩放、游戏改分辨率）时重建；每次要画新东西前先比对一次显示器，防止漏掉变化事件。
- 显示器编号：主显示器是 1 号，其余从左到右、从上到下。队友的信号、鼠标按「几号显示器 + 宽高比例」传，落到自己同号显示器的同一比例处，没有这一号就落到 1 号。
- 坐标：钩子给物理像素，按显示器缩放换成窗口内的 CSS 像素。
- 画面：移植 lolPing `src/renderer/overlay` 的轮盘（SVG）、信号动画、表情舞台、文字排布和音效（Web Audio，开窗口时一次解码）。对线模式下另画对手的小英雄、700 码圈、充能圈、冷却倒计时和心之钢爆炸特效。

## 4. 队伍（`team`）和状态同步

沿用 1.x 的事件模型：每条状态事件由作者用 Ed25519 签名、按作者和序号排列，经 Have/Want 补齐，所有人推导出一样的队伍状态（1.x 架构第 4、7、8 节）。2.0 的改动：

- 只留状态流：`TeamCreate`、`Join`、`Leave`、`Profile`、`Rename`、`Dissolve`、`Hit`。1.x 的聊天流、聊天补齐（WantFloors/Floors）、图片、清空记录、规则修改都去掉。
- 包头的协议版本从 1 改为 2；1.x 的程序收到会提示「对方版本不同」。
- 队伍码沿用 1.x 的格式（另换前缀，和 1.x 的群码区分开）。

## 5. 实时帧（`live`）

不入库、不补齐，丢了就丢了。每帧都带发送者短 ID 和序号，并用发送者的身份密钥签名；收的人按序号窗口和 ±10 分钟时间戳挡住重放（lolPing 12 节）。

| 帧 | 内容 | 频率 |
|---|---|---|
| Presence | 状态（在线、暂停、离开电脑）、是否开对线模式、程序版本、表情轮盘上的自定义图哈希 | 局域网 2 秒一次，中继 5 秒一次 |
| Cursor | 显示器号、x、y（0–65535 比例）、序号 | 只在对线模式、鼠标移动时发；局域网最多每秒 30 次，中继每秒 3 次 |
| Charge | 对谁开始充能、取消 | 状态变化时发 |
| Ping / Emote / Text / Alive | 同 lolPing，位置用显示器号加比例 | 按发送预算 |
| Vote / Ballot | 同 lolPing 14 节 | 同上 |
| Want / Chunk | 自定义表情静态图分片 | 同 lolPing 13 节 |
| Bye | 离开队伍 | 一次 |

发送预算：中继沿用每秒 5 条、突发 10 条，优先级从高到低：信号表情文字命中 > 在线状态、充能、Have > 鼠标位置（只留最新一条）> 补齐。局域网不受这个限制，只受防灌水限制。

## 6. 对线和心之钢

### 6.1 对线判定（`laning`，纯函数）

输入：自己的鼠标（显示器号、物理坐标）、每个对手最新的鼠标帧（带收到时间）、时间。输出：每个对手的状态（远、在范围内充能中、充能完成、冷却中）和出手结果。

- 对手的位置：用最近两帧做线性插值，超过 1 秒（中继 2.5 秒）没新帧就当离线，充能中断。
- 范围（「700 码」）：同一号显示器上，距离不超过该显示器较短边的 35%（1080p 上约 380 像素）。这个比例是常量，实测后再调。
- 充能：在范围内连续 3 秒；出范围、对手关掉对线模式、对手掉线都会中断，重新计时。充能开始和中断各发一次 Charge 帧。
- 出手：Alt+单击。落点离某个充能完成的对手不超过较短边的 6%（至少 60 像素）就算命中，所有满足条件的对手都命中。点空了，这次的充能全部作废。
- 判定以出手一方看到的位置为准（「射手优先」），所以跨网时也能打中；对手看到的是事后的结果。

### 6.2 Hit 事件和重放（`heartsteel`，纯函数）

- Hit 事件（状态流，签名）：`target`（对手完整公钥）、`charged_ms`（这次充能用了多久）。
- 有效条件（所有人用同一套规则重放，所以层数一致）：
  - 作者和目标在事件时间都是队员，目标不是自己；
  - `charged_ms ≥ 3000`；
  - 作者对同一个目标的上一条有效 Hit 至少早 30 秒（按作者时间，作者时间严格递增）；
  - 不在队伍解散之后。
- 层数 = 作者的有效 Hit 数；被叠次数 = 以他为目标的有效 Hit 数。
- 生命值（整数运算，各端结果一样）：初始 1500；每叠一层，伤害 = 70 + 当前生命值 × 6 / 100，生命值 += 伤害 / 10。数值仿照心之钢「伤害随最大生命值增长、每层得到伤害 10% 的永久生命值」。
- 实时特效：收到的 Hit 有效、而且是实时帧带来的，就在目标位置放心之钢爆炸特效和音效；补齐来的旧 Hit 只更新数字。

### 6.3 跨网的实时性

- 局域网：每秒 30 帧，几毫秒延迟，很顺。
- 跨网：公共中继延迟 0.2–0.5 秒，每秒只发 3 帧，靠插值补帧，看起来会一顿一顿。命中按出手方判定，所以仍然能玩。
- 打洞直连仍是以后的事；做了以后跨网也能每秒 30 帧。

## 7. 表情（`emotes`）

- 内置表情：lolPing 的 `assets/emotes`（动画 WebP、图标、音效）和它的清单。
- 导入：静态图压到 12KB、160 像素以内，按 SHA-256 前 32 位十六进制命名；可另存原动画（5MB 以内）和音效（1MB、5 秒以内）。规则同 lolPing 13 节。
- 传图：在线状态里带上自己轮盘上的自定义图哈希；没有的人用 Want 要，用 Chunk 分片发静态图，收齐核对哈希再存进缓存（最多 200 张、4MB）。动画和音效不传。

## 8. 存储和设置

- 新数据文件 `gang2.db`，和 1.x 的 `lolgang.db` 放在同一目录；1.x 的文件不读、不删。主密钥沿用凭据管理器里的那一个，身份在新库里重新生成。
- 表：身份、队伍、成员缓存、状态事件、设置；自定义表情放在 `emotes/` 目录，队友的静态图放在 `emote-cache/`。
- 设置项：lolPing 8.1 节的全部（触发键、拖动距离、单击信号、轮盘、快捷键、大小、时长、音量、静音、刻度声、开机启动、功能开关、打字键、面板键、文字样式），加上对线模式的快捷键和 1.x 的主题、网络设置。

## 9. 素材和许可

## 10. 测试

- 纯函数单元测试：手势状态机（移植 lolPing `helper_tests.cpp` 的用例）、轮盘选格、显示器编号和坐标换算、对线判定、叠层重放和生命值公式、帧的编解码和校验、投票计票、文字清洗、表情导入检查。
- 节点集成测试：两个节点经局域网和假中继交换在线状态、信号、鼠标帧、Hit 事件，双方层数一致。
- 必须在真机上手动验：键鼠拦截和放行、透明窗口、多显示器和不同缩放、声音、截图工具、全屏游戏。

## 11. 风险

| 风险 | 应对 |
|---|---|
| 全局键盘钩子可能被杀毒软件当成键盘记录器 | 和 lolPing 一样无法完全避免；钩子只看按键码、不记录、不外发，在 README 说明 |
| 钩子回调慢被 Windows 移除 | 回调只做纯计算；看门狗检测钩子失效后重装，并在托盘提示 |
| 安装包变大（素材约 60MB） | 只打包清单里用到的文件 |
| 跨网对线卡顿 | 插值、射手优先；以后做打洞直连 |
| 公共中继限流 | 鼠标帧最低优先级、只留最新一条 |
