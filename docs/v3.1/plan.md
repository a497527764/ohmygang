## 风险

- **M1 删得不干净**：Linux 的代码散在 input、api、update、前端几处，漏删会编译不过或留下没人用的代码。
  删完全文搜一遍 `linux`、`x11`、`deb`、`inputWarning`。
- **M2 只通知可能不够**：个别机器的图标缓存不认这个通知。那样就在更新时重建桌面快捷方式，所有者那台已经是旧图的电脑正好拿来验证。
- **M3 缓存出错比慢更糟**：持有情况算错了，会少要或多要事件，队伍信息同步不上。单元测试覆盖每一种写入事件的路径
  （自己写、收到队友的、补齐来的），两实例实测进队、改名、退出、解散都照旧。
- **M5 内容安全策略**：配错会白屏，或者表情图、音效、和 Rust 的通信被挡。每个窗口实测后再发版；有问题就先不加，单独再做。
- **macOS 没有真机**：M1–M5 在 macOS 上只能靠 CI 编译和纯逻辑测试，标注「没在真机上验证」。
