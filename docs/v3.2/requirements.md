## 1. 代码结构（R1，S1、S2）

只搬代码、不改行为：函数原样挪过去，可见性按需要放宽到 `pub(super)`，模块路径跟着改。单独一个提交，diff 里只有搬家，全部测试照旧通过。

- **S1** `team.rs`（714 行）一个文件干四件事 → `team/` 目录：
  - `mod.rs`：队伍状态（`TeamState`）、投票人列表、几个共用小工具

- **S2** `panel.rs`（832 行）管三样窗口 → `panel/` 目录：`mod.rs`（线程、消息、队伍面板、建窗口和摆位置）、`vote.rs`（投票）、`text.rs`（聊天框）

## 2. 去掉 2.0.1 的迁移安装逻辑（R2）

`src-tauri/windows/hooks.nsh` 99 行里，除了 3.1.1 加的「装完通知 Windows 刷新图标」，其余都是从「钢一下」迁过来时用的：
找旧的安装目录、自动更新时改装到旧目录旁边、静默运行旧目录里的 `uninstall.exe`、补快捷方式。所有者确认大家都已是 3.1.2，可以删。

- 删掉以后钩子只剩 `SHChangeNotify` 一行。
- **安全上也有好处**：现在安装包（包括每次自动更新）会去看桌面和开始菜单里叫「钢一下」的快捷方式，运行它指向的目录里的 `uninstall.exe`。
  有人在桌面放一个伪造的同名快捷方式，安装时就会运行他的程序（权限和用户一样）。删掉就没有这条路了。
- 万一还有人装着 2.0.0「钢一下」：直接装 3.2.0 时旧的不会被卸掉，两个并存（数据目录本来就是同一个），手动卸掉旧的即可。

## 3. 中继少发（R3，P7）

3.1.1 的评估：经中继说话时，每个 400 毫秒的语音帧签成约 1.7 KB 的事件，发给全部 8 个中继，每人上行约 34 KB/秒，听的人从每个中继各收一份；
只发最好的 3 个约 13 KB/秒，上下行都省约六成。风险是发和听两边连着的中继不一定重合。3.2.0 按所有者的意思先测再定：

1. 每个中继记**回显成功率**（发出的事件 25 秒内从自己的订阅里收到的比例，看最近一段）和回显延迟，关于页或调试信息里能看到。
2. **实测**：两个测试实例只走中继（开发用的开关关掉局域网），各发一串探测包，统计「发全部 8 个」和「只发回显最好的 3 个」两种方式下对方收到的比例和延迟。
3. 数字出来后所有者决定改不改。改的话：发给回显成功率最高的 3 个（掉线或被限速就换下一个），收照常全听。

## 4. 性能（R4）

### 4.1 先量出来的现状（3.1.x 正式版构建，测试实例，控制面板关着，空闲）

- **钩子**：低级鼠标钩子 `WH_MOUSE_LL` 和键盘钩子 `WH_KEYBOARD_LL` 一直装着。全系统**每一次鼠标移动**（游戏鼠标每秒上千次）都要切到我们的线程、跑一遍手势状态机，
  即使没按触发键、即使信号暂停着。键盘事件少得多。
- **CPU**：程序进程空闲约 0.2–0.6 秒/分钟（3.1.1 已经从约 1 秒降下来）；网页进程空闲已经是 0。
- **线程**：程序进程 **63 个线程**。其中大约一半是异步运行时的工作线程：Tauri 默认「一个逻辑核一个」，这台电脑 32 个逻辑核。
- **定时唤醒**（没事也会醒）：节点每 100 毫秒；每个中继连接每秒一次（8 个）；投票线程每秒一次；查显示器每 3 秒；在线状态每 5 秒。
- **内存**：合计约 260–400 MB。显卡进程 108–238 MB（随用过的窗口变），WebView2 主进程约 47 MB，每个网页进程 37–41 MB，程序本身约 37 MB。
  队伍面板、投票、聊天框用过一次后**只藏不销毁**，每个一直占一个网页进程。透明窗口空闲时只是挪到屏幕外，**尺寸还是整块屏幕**，显卡缓冲一直占着。
- **磁盘和下载**：安装包 59 MB、exe 66 MB。打进去的前端资源 54 MB，其中**表情动图 47.7 MB**（44 个，每个 1.1–1.5 MB），提示音 WAV 3.6 MB。
  WebView2 的配置目录 33 MB，其中广告拦截列表 12 MB、组件下载 4.5 MB、语音识别 2.6 MB、统计 2.5 MB、断字词典 1.7 MB——程序都用不到，而且是 WebView2 在后台联网下载的。
  程序自己的数据很小（数据库约 0.2 MB）。

### 4.1.1 M3 基线（2026-11-10，3.2.0-M2 的正式版构建 = 3.1.2 的性能，测试实例 2，控制面板关着，不开调试端口）

| 项目 | 数字 |
|---|---|
| 空闲 60 秒，程序进程 CPU | 299 毫秒：异步工作线程（节点、中继）合计约 200，表情传输线程 31，透明窗口线程 16，主线程 16，投票线程 16 |
| 线程数 | 64（其中异步工作线程 32 个） |
| 内存合计 | 339 MB：显卡进程 185，WebView2 主进程 47，透明窗口网页进程 38，程序本身 37，其余 32 |
| 鼠标移动的代价 | 10 秒里 2500 次 1 像素的移动，钩子线程 109 毫秒，约 44 微秒一次。游戏鼠标每秒 1000 次时，**只要鼠标在动，就一直占一个核的 4–5%**，没按触发键时也一样 |
| 安装包 / exe / 前端资源 | 59 MB / 66.8 MB / 54 MB（表情动图 47.7 MB、WAV 3.6 MB） |

### 4.2 改法

| 编号 | 问题 | 改法 |
|---|---|---|
| H1 | 鼠标钩子一直装着 | 只在需要时装：按下信号或表情的触发键时装上，松开、手势结束后摘掉；信号暂停时不装。触发键是鼠标侧键时只能一直装（只有钩子能拦住侧键），见决定 2。离开电脑的判断改用 `GetLastInputInfo`（系统记的最后一次输入时间），面板放在哪块屏幕改用 `GetCursorPos`，都不需要钩子。macOS 不动（没法在真机上验证） |
| H2 | 键盘钩子回调 | 保留（说话键、面板键要分按住和点按，只能靠它）。复查回调：只查表、不分配内存、不等锁 |
| T1 | 32 个异步工作线程 | 自己建运行时交给 Tauri：2 个工作线程，线程起名（以后量得出是谁在耗） |
| T2 | 空闲时的定时唤醒 | 逐个量，能改成「有事才醒」的改：投票线程只在有投票时每秒走一步；中继连接只在有等回显的事件时才每秒查；节点按最近的到期时间睡。查显示器每 3 秒一次很便宜，量过再定 |
| W1 | 队伍面板、投票、聊天框只藏不销毁 | 藏起来一段时间后销毁，下次用时再建（见决定 1） |
| W2 | 透明窗口空闲时尺寸还是整块屏幕 | 试：空闲时缩成很小。量显卡进程内存和再次显示的延迟，省得多又看不出卡才留 |
| W3 | WebView2 后台下载用不到的组件 | 启动参数关掉组件更新和后台联网（所有窗口的参数必须一样，主窗口写在 `tauri.conf.json`）。验证：新的配置目录里不再出现这些目录 |
| A1 | 表情动图 47.7 MB、WAV 3.6 MB | 重新压缩：动图按最大显示尺寸缩、适当降质量；WAV 降采样。目标：安装包从 59 MB 降到 15 MB 左右。所有者看过效果再定（决定 4）。<br>**M7 实际做法**：尺寸不能缩（表情大小拉到最大时画成 375 个 CSS 像素，比 320 像素的原图还大），WAV 也不能降采样（不少信号音效有 5–25% 的声音在 11 kHz 以上，降到 22 kHz 听得出来），所以 15 MB 做不到。改成：动图的透明边缘从几乎不损改成分 56 级（透明数据原来占动图的六成），PNG 无损重新压缩，左右声道几乎一样的 4 个 WAV 改单声道。所有者看了三档对比（16 级：柔光有台阶；56 级；每秒 15 帧：动作不顺）选了 56 级 |
| U1 | 测试实例也查更新：版本号旧的测试版会在所有者屏幕上提示「可以更新」（2026-11-10 实际发生，所有者因此手动重装了一次） | `LOLGANG_INSTANCE=2/3` 的测试实例不查更新 |

## 5. 内存安全（R5）

- **unsafe**：只在 `input/win32.rs`（20 处）和 `input/macos.rs`（21 处），都写了中文 SAFETY 注释。改成**编译器保证**：整个 crate 禁止 `unsafe`，只给这两个文件放开；逐处复查。H1 会改到 `win32.rs`，新写的同样注释。
- **panic**：正式版是 `panic = "abort"`，任何一处 panic 程序直接退出（信号、钩子全没了）。查遍非测试代码的 `unwrap()`、`expect()`、下标越界：
  外来数据（网络包、文件、页面传来的参数）的路径上一律改成返回错误、丢弃；只留「锁没有中毒」这类不会失败的。
- **外来数据**：上限已经齐全（见第 7 节）。补测试：截断的包、超长字段、深层嵌套的 CBOR、坏图片，保证只丢弃、不崩、不卡。
- **依赖漏洞**：见决定 5。

## 6. 软件和系统安全（R6）

| 编号 | 问题 | 改法 |
|---|---|---|
| SEC1 | 控制面板有 `core:default`（窗口、菜单、托盘、路径、图片等核心接口都能调），实际只用到事件和读版本号；所有窗口都能调所有 Rust 命令（比如透明窗口能调 `settings_write`） | 最小授权：控制面板只给事件、读版本号和它用的命令；透明窗口只能调 `overlay_hello`、`overlay_idle`；队伍面板、投票、聊天框只能调各自的命令（Tauri 的 app manifest 给每个命令一个权限）。按 AGENTS 先说明风险：给少了页面会报错，所以每个窗口实测（见决定 6） |
| SEC2 | 安装包会运行快捷方式指向的 `uninstall.exe` | R2 删掉 |
| SEC3 | 键盘钩子看得到全系统的按键 | 复查并写进文档：按键不存、不记日志、不发出去，只认设置里那几个键 |
| SEC4 | 局域网包头、中继标签里房间编号是明文 | 内容是加密的，房间编号由房间码派生、推不出房间码；同一网络或同一中继上的人能看出「有这么一个队伍、什么时候在发」。记下，不改（要动协议） |
| SEC5 | 自动更新 | 已有：签名校验、`requireSignedVersion`（防拿旧版的真包冒充新版）、HTTPS。不改 |
| SEC6 | `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量在正式版也生效（能开调试端口） | 只有本机这个用户能设，能设的人本来就能做更多。记下，不改 |
| SEC7 | 开机启动参数、再次打开程序时传来的参数 | 复查：参数不当成路径或命令用 |

## 7. 查过、没问题的（记下来，免得以后重查）

- **外来数据的上限**：网络包不超过 1200 字节，事件内容不超过 1 KB，昵称 32 字、队伍名 64 字、文字 120 字（去掉控制符和隐形字符），
  时钟偏差超过 10 分钟的实时帧丢掉，表情图传输有个数和字节上限，中继收包每秒最多 200 个，局域网有洪水防护。
- **加密**：包用房间密钥 XChaCha20-Poly1305 加密并带认证，事件有签名；主密钥在系统凭据管理器里。
- **页面**：内容安全策略 3.1.1 已加，队友的文字一律当纯文本显示。
- **本机数据**：数据库约 0.2 MB，历史记录有条数和语音大小上限。
